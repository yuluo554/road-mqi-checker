> 回答三个问题：**台账与检测表长什么样**、**破损字典怎么界定**、**真值文件与 manifest 的语义是什么**。
> 本文件是 M1 的出口判据之一，也是 `bench/generator.py`、`ledger/importer.py`、`ledger/checks.py`
> 三者字段的唯一文档来源：**代码里单点定义的词汇，本文件只引用不另写一套**。
> 版本：v1（2026-10-07，M1 定稿）

## 〇、先说清楚本文件里"数字"的性质

本题的立身之处是**未核对的系数一律不进评定路径**（见 `plan/02` §4）。所以：

- 本文件**不出现任何规范阈值数字**：扣分比率、分项权重、分级边界、闭合差容差一律写成
  "以原文核对后入库"，其登记表是 `data/README.md` §一 与内置规则集
  `src/road_mqi_checker/rulesets/base-jtg5210-2018.json`（15 格全 `pending`）；
- 本文件出现的其它数字（长度米数、数量、桩号、板数）**全部是演示数据自身的取值示例**，
  属于"这份合成数据长这样"，不是任何标准的限值；
- 破损字典里的量纲（m / m2 / 块）与"哪类破损按长度、哪类按面积"是**口径**而非阈值，
  同样标"待核对"：M3 逐格核对原文后，若与本文登记的合成口径不符，以原文为准并同步本表。

## 一、四级数据结构

```
路线（route） ── 按年度声明里程区间
  └── 路段划分（segment，主键 segment_id + year）  ← 跨年划分变更就是这张表的变化
        └── 年度检测记录（survey，一个路段一年一行）  实测指标 + 报告信息
              └── 破损调查行（distress，多行）       破损类型 × 程度 × 数量 × 量纲
```

导入的**物理文件**是一张宽表（检测单位实际导出的形态）：一行 = 一条破损调查记录，
路段与实测指标列在该路段的各行间重复。导入器把它拆回上面四个逻辑对象，
并要求**同一对象在各行间完全一致**（不一致按 `R009` 拒入，不静默取首行值）。

### 1.2 台账表（`ledger.db.DDL`，7 张，schema v2）

| 表 | 主键 | 装什么 | M1 变化 |
|---|---|---|---|
| `route` | `route_id + year` | 路线按年度的里程声明 | — |
| `segment` | `segment_id + year` | 该年度的路段划分 | **新增可空列** `lane_count` / `segment_width_m` / `panel_count` |
| `survey` | `segment_id + year` | 实测指标 + 报告信息 | — |
| `distress` | `row_id` | 破损调查行，带 `source_row_no` 回指文件行号 | — |
| `import_receipt` | `receipt_id` | 每次导入的汇总与拒因摘要 | 开始写入 |
| `partition_change` | `route_id + year_from + year_to + change_kind + segment_id` | 跨年划分变更清单 | 开始写入 |
| `meta` | `key` | `schema_version` | 值升为 `2` |

**为什么把 `lane_count` / `segment_width_m` / `panel_count` 提进台账**（schema v2 的唯一理由）：
"破损数量的几何上界"是超范围检出的判据，水泥路面按板数计更是扣分换算的分母。
它们只活在 CSV 里的话，台账就没法复算校验，也撑不住 M2 的评定。三列可空，
**缺了就只能判"未判定"**（`check_value_range` 给出 `undetermined`），不许默认合格。

**表上不设 CHECK 约束**（M0 定的纪律，M1 落地时保持）：负值、超范围、单位错都要能进库，
否则"导入回执 + 异常识别召回"这条主证据链就断了。

## 二、破损类型 × 程度字典（`ledger.models.DISTRESS_DICTIONARY`）

程度档位两套路面共用：`轻 / 中 / 重`（顺序由好到差）。字典只登记"类型名 + 计量量纲 + 上界类别"，
**不登记任何扣分比率**。

### 2.1 沥青路面（`surface_type = asphalt`）

| 破损类型 | 量纲 | 数量含义 | 几何上界类别 | 核对状态 |
|---|---|---|---|---|
| 纵向裂缝 | `m` | 该车道内该型裂缝的累计长度 | 长度 × 车道数 | ⬜ 待核对 |
| 横向裂缝 | `m` | 同上 | 长度 × 车道数 | ⬜ |
| 斜向裂缝 | `m` | 同上 | 长度 × 车道数 | ⬜ |
| 网状裂缝 | `m2` | 该型破损的累计面积 | 路段平面面积 | ⬜ |
| 坑槽 | `m2` | 同上 | 路段平面面积 | ⬜ |
| 松散 | `m2` | 同上 | 路段平面面积 | ⬜ |
| 沉陷 | `m2` | 同上 | 路段平面面积 | ⬜ |
| 泛油 | `m2` | 同上 | 路段平面面积 | ⬜ |
| 波浪 | `m2` | 同上 | 路段平面面积 | ⬜ |
| 啃边 | `m` | 沿路基边缘的累计长度 | 长度 × 车道数 | ⬜ |

### 2.2 水泥混凝土路面（`surface_type = cement`）

| 破损类型 | 量纲 | 数量含义 | 几何上界类别 | 核对状态 |
|---|---|---|---|---|
| 破碎板 | `块` | 板块数 | 该路段板块总数 `panel_count` | ⬜ |
| 板角断裂 | `块` | 板块数 | `panel_count` | ⬜ |
| 坑洞 | `块` | 板块数 | `panel_count` | ⬜ |
| 错台 | `块` | 板块数 | `panel_count` | ⬜ |
| 隆起 | `块` | 板块数 | `panel_count` | ⬜ |
| 裂缝 | `m` | 裂缝累计长度 | 长度 × 车道数 | ⬜ |
| 板边剥落 | `m` | 剥落沿板边的累计长度 | 长度 × 车道数 | ⬜ |
| 接缝料损坏 | `m` | 接缝料失效的累计长度 | 长度 × 车道数 | ⬜ |

> 字典的作用边界：它只回答"这条记录能不能解释成一个可复算的破损量"。
> 某型某度的破损扣多少分**不在这里**，在规则集 `deduct_ratio.*` 那一格，现在还是 `pending`。
> 类型名与量纲若与原文不符，M3 核对后以原文为准，并同步本表与 `models.DISTRESS_DICTIONARY`
> （两者由 `test_m1_pipeline.py` 的字典用例对账，改一处就会红）。

## 三、实测指标的定义域（不是分级阈值）

`models.INDICATOR_DOMAIN` 只登记**指标自身不可能取到的值**，用于 `value_range` 检出录入错误；
"多少分算良"这类分级边界一律留待 M3 核对。

| 指标 | 定义域 | 越界意味着 |
|---|---|---|
| `rqi` | `[0, 100]` | 指数超出其定义，记录不可能为真 |
| `rut_depth_mm` | `[0, +∞)` | 负车辙不可能 |
| `skid_indicator`（`SFC` / `BPN`） | `[0, 100]` | 同上 |

**缺测与 0 的区分**：空值 → 台账里是 `NULL`，表示"没测"；填 `0` 会被加权当成真值。
水泥路面的 `rut_depth_mm` 就是这条规则的固定用例（`test_missing_measurement_stays_null_not_zero`）。

## 四、规模口径与生成规则（`bench/generator.py`）

| 项 | 口径 | 改动后果 |
|---|---|---|
| 规模 | 3 条虚拟路线 × 4 个年度 = 12 份检测表 | 基准规模口径，改动即漂移 |
| 路线 | `S99`（沥青）、`X990`（水泥）、`Y999`（沥青） | 编号形态受白名单约束 |
| 年度 | 2022–2025（`DEFAULT_YEAR_START = 2022`） | 虚构年度 |
| 随机源 | 只有 `bench.rng.SplitMix64`，默认 seed `20261007` | 换源即不可复现 |
| 路段数 | 每路线每年 3–5 段，合计 42 个"路段 × 年度"对象 | 见 `PARTITION_PLAN` |
| 破损行 | 每对象 1–3 条正常老化 + 1 条局部突发损坏 | 数量由 seed 决定 |
| 注入用例 | **声明的常量** `INJECTIONS`，19 例覆盖八类 | 不随 seed 漂移（有测试锁定） |
| 产物 | `data/raw/<route>-<year>.csv` ×12、`data/truth/<route>-<year>.truth.csv` ×12、`data/raw/manifest.json` | 共 25 份 |
| 落盘 | 固定 LF、无时间戳、逐字节可复现 | `--force` 重跑 `git status` 零变化 |

损坏模式词汇 `SCENARIOS` 九个：`normal_aging`、`localized_damage` 每个对象都有；
其余七个与 `INJECTED_ISSUES` 同名，逐个对应 `INJECTIONS` 里的声明。

干净对照格子（无任何注入的"路线-年度"）：**S99-2023、X990-2025、Y999-2023**。
没有它们就测不出误报率——只有"本该什么都不报"的对象才能当分母。

## 五、真值文件语义（M1 定稿，`TRUTH_COLUMNS`）

一行 = 一个"路段 × 年度"对象，共 42 行/套。列序即 `bench.generator.TRUTH_COLUMNS`。

### 5.1 两类真值同源但口径不同

1. **数据错 → 检出**：`injected_issue` + `injected_field`。标记落点规则（唯一口径，别再猜）：

   | 注入类别 | 标记落在哪一行 | `injected_field` 写什么 |
   |---|---|---|
   | `gap_chain` / `overlap_chain` | 被移动边界的那个路段 | 被改的列名（`seg_start_stake` / `seg_end_stake`） |
   | `partition_change`（new / split / merged / shifted） | **变更产生的新对象**所在年度 | `segment_id` |
   | `partition_change`（disappeared） | 该路段**最后存在的那一年** | `segment_id` |
   | `negative_value` / `out_of_range` / `unit_error` | 被污染行所属路段 | `quantity` / `rqi` / `quantity_unit` |
   | `duplicate_import` | 重复行所属路段 | `row`（整行与前文完全相同） |
   | `none` | — | 留空 |

2. **分数算得对**：`pci_truth` / `grade_truth` / `mqi_partial_truth` / `recommended_action_truth`。
   生成器先查**规则集系数门**：本列受哪几格系数支配、那些格子是否 `computable`。
   内置包 15 格全 `pending`，所以这四列现在一律是

   ```
   pending:coeff=deduct_ratio.asphalt_distress,pci_component.ride_quality,...
   ```

   **未核对不出数，真值也一样不出数** —— 这不是省事，而是本题的立身之处：
   真值里凭记忆填一个 PCI，等于给基准装了一个假答案。
   系数核对完（M3）且评定引擎就位（M2）后，同一 seed 重跑这四列自动变成数值真值，
   且数值**来自评定引擎本身**（`_numeric_truth_probe` 这个唯一入口），
   不会出现"真值一份公式、引擎另一份公式"的假对账。

### 5.2 同一注入隐含的其余结论（`INJECTION_IMPLICATIONS`）

一条注入往往牵动别的校验项。**这些隐含结论不在真值里手工再写一份**——
真值列名是既定口径，手工二次结论一定会和实际数据漂移；改由单点声明的
`INJECTION_IMPLICATIONS` + 几何事实推断。举三条：

- `gap_chain`：移动边界 ⇒ 相邻年度同 id 路段应报 `shifted`；路段长度和 ≠ 路线里程 ⇒
  `length_closure` 报检出（M3 起容差格已显式登记为 ±1 m；容差退回 pending 时该判据只出"待核对，未判定"）；
  该路段自身仍可入库。
- `unit_error`：量纲不符 ⇒ 该行仍入库、由 `unit_consistency` 检出，
  而 `distress_dictionary` **不应**重复报同一行（类型本身合法）。
- `duplicate_import`：文件内完全重复行在**导入层**就被拒（`R008`），所以台账里查不到它 ——
  它的"检出"证据是回执，不是 finding。跨文件重复内容则由 `check_duplicate_import` 兜住。

### 5.3 检出证据的两层口径

| 校验项（`CHECK_KINDS`） | 对应拒因代码 | 证据出现在 |
|---|---|---|
| `stake_gap` | `R002_STAKE_GAP` | finding |
| `stake_overlap` | `R003_STAKE_OVERLAP` | finding |
| `length_closure` | `R004_CLOSURE_EXCEEDED` | finding（容差已登记 → 判检出；容差 pending 时结论是"未判定"，差值仍报出） |
| `distress_dictionary` | `R005_BAD_DICTIONARY` | finding |
| `unit_consistency` | `R006_UNIT_MISMATCH` | finding |
| `value_range` | `R007_OUT_OF_RANGE` | finding（负值/超界）或 `undetermined`（算不出上界） |
| `duplicate_import` | `R008_DUPLICATE` | 文件内重复 → **导入回执**；库内重复内容 → finding |
| `partition_change` | `R001_UNKNOWN_ROUTE`* | finding + 写入 `partition_change` 表 |

\* 划分变更借用 `R001`：变更后的年度里那个 `segment_id` 在台账中确实"未知"，
这正是它对跨年对比有害的原因。八个代码全部有活的用例，没有闲置词汇。

**导入层只拒"存不进台账"的行**：`R001`（一份表混进第二条路线）、`R008`（文件内完全重复行）、
`R009`（字段缺失/数值或桩号不可解析/年度不符/同一对象前后矛盾/标识符越界前的结构错）、
`R010`（合成数据的标识符不在白名单内）。
`R002`–`R007` 属语义级判据，由校验层出 finding —— 数据照进台账，问题照报出来。

### 5.4 实测结果（M1 收尾，py3.8.8 与 py3.12.10 双通道一致）

分母口径先说清，否则"1.00 / 0.00"这类数字没有意义：

- **格级六类**（悬空 / 重叠 / 字典 / 量纲 / 范围 / 重复）按"路段 × 年度"对象逐条对账：
  42 个对象里 10 个被格级注入标记（合计 12 例，同一对象可同时带两类）；
- **跨年划分变更**按"路线 + 年度对"对账：真值标 7 例，另有 6 条是 `INJECTION_IMPLICATIONS`
  声明的隐含结论（移动边界必然同时造成一次 shifted），合计 13 条检出，逐条可由几何复算验证。

| 指标 | 目标 | 实测 | 口径 |
|---|---|---|---|
| 数据异常识别召回 | ≥ 0.95 | **1.00** | 格级 12/12（其中 2 例的证据是导入回执 `R008`，10 例是 finding）+ 划分变更 7/7 标记与 6/6 隐含结论全部检出 |
| 数据异常识别误报 | = 0 | **0.00（0/32）** | 未被格级注入标记的 32 个对象上，格级六类零检出；`distress_dictionary` 与库内 `duplicate_import` 在整套数据上全程 0 条 |
| 产物位级一致 | 两次逐字节一致 | **通过** | 同 seed 重生成与入仓数据逐份 sha1 相同；`rmqc bench generate` 不改写任何文件（`files_changed=0`），换 seed 才需要 `--force` |
| 导入行数 | — | 139 行 → 137 入库 / 2 拒入 | 拒入全是 `R008_DUPLICATE`，逐条带文件行号与路段编号 |
| 校验结论 | — | 27 条 = 27 检出 + 0 未判定 | M3 起容差格（±1 m，用户自定）已显式登记 → 原 4 条"未判定"的闭合差全部转为检出（实测差值 −200 / +100 m）。用容差退回 pending 的临时包重跑，同一批仍是 4 条"未判定"，差值照报 —— 见 `test_m1_pipeline.py` 两条同名门 |

复现命令：`rmqc bench generate --seed 20261007` 后逐年 `rmqc import`，
或跑 `python -m pytest tests/test_m1_pipeline.py -k "recall or false_alarm"`。

## 六、manifest 格式（`data/raw/manifest.json`）

顶层键固定为 `MANIFEST_TOP_LEVEL_KEYS`（顺序无关，写出时 `sort_keys=True`）：

| 键 | 内容 |
|---|---|
| `data_class` | 固定 `SYNTHETIC` |
| `dictionary_version` | 破损字典版本，本文件 §二 改动时同步 |
| `generator` | 产出模块 key（`road_mqi_checker.bench.generator`） |
| `seed` / `routes` / `years` | 规模与随机入口 |
| `schema` | `raw_columns` 与 `truth_columns` 的**列清单**（自描述，读侧不必另抄） |
| `files` | 每格一条：文件名、`route_id`、`year`、行数、**raw/truth 的 sha1**、`scenarios`、`injected_issues`、`injections`（含 `detail` 说明） |
| `totals` | 行数合计、注入用例数、按类别分布、干净对照格子清单 |
| `coefficient_gate` | 生效/拒算系数格数 + 一句 `truth_note`（为什么真值四列是 pending 令牌） |

三条纪律：注入说明只出现在 manifest 与 truth，**不出现在 raw**；
`sha1` 让"文件有没有被改动"成为可核对事实（`test_manifest_digests_match_committed_fixtures`）；
不带任何时间戳字段。

## 七、数据类别与隐私红线（`importer.DATA_CLASSES`）

| 类别 | 触发方式 | 白名单 | 说明 |
|---|---|---|---|
| `SYNTHETIC` | 文件首行 `# data_class=SYNTHETIC` | **强制** | 演示与评测数据。真实形态标识符（`G25`、`110101`、138 号段…）逐行拒入 `R010` |
| `user` | `--data-class user` 显式声明且文件无标记 | 不施加 | 用户自己的真实台账。本题的用途就是管真实检测账，白名单是**演示数据的红线**，不是把工具锁死 |

- 两边都声明且冲突 → 拒读（不静默降级）；
- 没有标记又没声明 → 拒读（退出码 2）。红线不能靠"猜这是不是演示数据"来守；
- 回执里 `data_class` 与来源 digest 一并落库，事后能查这份账是以什么身份进来的。
