# 07 · 交付与打包（M6）

> 本文件是 M6 的出口判据主文档：交付层三件事——**报告导出**、**桌面壳**、**PyInstaller 打包**——
> 各自的结构、口径与实测结果。命令面口径见 `plan/02` §六，既定条款清单见 §九（M6 追加第 33–35 条）。
> 一句话前提：**交付面仍然不出数**（规范来源 14 格系数未解锁），所以这一层做的是
> "把拒算事实完整、可核、无泄漏地交出去"，不是"把界面做得像有结果"。

## 一、报告导出（`report.exporters`）

### 1.1 三种格式与它们的分工

| 格式 | 实现 | 用途 | 字节口径 |
|---|---|---|---|
| `csv` | 标准库 `csv`，`lineterminator="\n"` | 喂给表格/数据库的机读清单 | 与 `.gitattributes` 的 LF 口径一致，跨平台逐字节相同 |
| `md` | 竖线表格 + 说明行 | 评审与留档的可读版 | 同上 |
| `docx` | **标准库直写 OOXML**（不引 python-docx） | 交付给业主/养护部门的 Word 件 | zip 三部件固定顺序 + 固定 `ZipInfo` 时间戳 `1980-01-01 00:00:00` |

docx 包内只有三个部件，任何一份导出物都是同一个 zip 骨架：

```
[Content_Types].xml      # Default: rels/xml + Override: /word/document.xml
_rels/.rels             # 只有一个 officeDocument 关系（.rels 里不写 Override，见 §5 坑）
word/document.xml       # 标题段 + 各表（w:tbl）+ 说明段 + 免责声明两段 + sectPr
```

### 1.2 两份文档的结构

| 文档 | 函数 | 内容顺序 |
|---|---|---|
| 评定结果报告 | `export_assessment_report(path, fmt, ledger_snapshot, pci_results, mqi_results)` | 台账概况表 → 路段 PCI 评定表 → MQI 汇总与分级表 → 三条口径说明 → **固定免责声明两行** |
| 优先序清单 | `export_priority_list(path, fmt, rows)` | `PLAN_COLUMNS` 16 列的清单表 → 三条口径说明 → **固定免责声明两行** |

三条结构约束（都被测试锁住，不是约定）：

1. **只能经 `report.disclaimer.compose_document` 拼文档** —— 免责声明必在末尾是结构事实，
   同时该函数在拼接时对全文调 `assert_honest_wording`；
2. **产物不带时间戳、不带绝对路径、不带本机用户名** —— 导出层自己再查一遍（§1.3），
   台账只出文件名（`ledger.sqlite` 而不是 `D:\…\ledger.sqlite`）；
3. **blocked / uncomparable 对象原样出现在表里，数值列留空**（不是 0、不是 `None`、不是 NaN），
   不许为了"报表好看"过滤行——过滤就等于把拒算对象从交付面上抹掉。

### 1.3 导出层自带闸门 `assert_export_safe`

设计立场：**不假设上游命令面已经拦干净**，交付层在自己通路上再拦一次。四类命中即 `PrivacyViolation`（退出码 2）：

| 查什么 | 规则 | 拒因里给什么 |
|---|---|---|
| 过强结论 | `privacy.BANNED_ASSERTIONS`（已确认 / 已核实 / 最终确定 / 必定） | 命中的词逐个点名 |
| 夹具污染 | 文本含 `fixture`（不分大小写） | "夹具值不进交付面" |
| 绝对路径 / 家目录 | `[A-Za-z]:[\\/]`、`\\\\`、`/home|Users|mnt|var|usr|tmp/` | 命中片段 |
| 时间戳形态 | `YYYY-MM-DD HH:MM:SS` | "落盘产物必须无时间戳" |

外加本机用户名（`USERNAME` / `USER`，`root`/`admin` 除外）出现在内容里即拒绝。

### 1.4 字段口径：导出层不产生任何新数字

清单行的合成规则在 `plan_rows()`：`grade` 从 **PCI payload** 转述、`delta` 与
`deterioration_rate_per_year` 从 **年对比 payload** 转述、其余字段从 **对策 payload** 转述，
四份结构体都是 `plan/HANDOFF-M6` §〇 第 1 条点名的既有 `result_payload()`。
未给 `--from-year` 时这两列**留空**，不做"用相邻年度推测"的摊分。
`_scalar()` 不做二次舍入——引擎已经按 `PCI_DECIMALS` / `SHARE_DECIMALS` 定过精度，
报告里再舍一次就会出现同一个数在 CLI 与 Word 里两种写法。

### 1.5 命令面

```bash
rmqc --db ledger.sqlite report --year 2022 --out assessment.md              # 评定报告（默认 scope/format）
rmqc --db ledger.sqlite report --year 2022 --format docx --out assessment.docx
rmqc --db ledger.sqlite report --year 2023 --scope plan --from-year 2022 --format csv --out plan.csv
```

退出码：导出成功但存在降级对象 → **1**（内置系数包下必然是这个）；该年度台账无路段行、
导出目录不存在、`--out` 后缀与 `--format` 不符 → **2**；**不再返回 3**。
两次同参数导出逐字节一致（三格式各自被测试锁住）。

## 二、桌面壳（`gui.app`）

### 2.1 页签 = 业务链条顺序

| # | 页签 | 转发的内核命令 | 页面参数 |
|---|---|---|---|
| 1 | 台账与导入 | `rmqc import` | 台账路径 / CSV 路径 / 年度 / 数据类别 / 只预检 |
| 2 | 路面 PCI 评定 | `rmqc assess` | 台账路径 / 年度 / 路段号 |
| 3 | MQI 汇总与等级 | `rmqc aggregate` | 台账路径 / 年度 / 汇总层级 |
| 4 | 年对比与优先序 | `rmqc compare` | 台账路径 / 基准年度 / 对比年度 / 路段号 |
| 5 | 基准评测 | `rmqc bench run` | 台账路径 / seed（留空即冻结基准） |
| 6 | 依据登记与规则集 | `rmqc ruleset list` | 静态说明行（不进 argv） |
| 7 | 导出与声明 | `rmqc report` | 台账路径 / 年度 / 导出内容 / 层级 / 格式 / 文件名 / 变化率基准年度 |

### 2.2 只转发，不另起第二套行为

- 页签→命令的映射由 `PAGE_TITLES` / `PAGE_COMMANDS` / `PAGE_SPECS` 三处声明，
  测试逐条对账（顺序、命令、字段名）；
- 每页"运行内核"按钮 → `build_argv(spec, 表单值)` → **`cli.main(argv)`**，
  退出码与输出文本与命令行逐字一致；GUI 不调引擎函数、不自建取数通路、
  不重定义"什么算成功"；
- **GUI 不许发明参数**：有一条门把每个页面要发的 flag 逐个拿去 `cli.build_parser()` 里找，
  找不到就红；空值一律不传（交回内核默认值与校验），不本地猜；
- `run_kernel()` 里 argparse 的参数错误按内核既有口径显示（退出码 2 + "参数不完整"），
  桌面壳不会因为用户少填一项就整窗消失。

### 2.3 缺依赖与探针

| 情况 | 命令 | 退出码 |
|---|---|---|
| 未装 PySide6 | `rmqc gui` 或 `rmqc gui --probe` | **1** + `pip install road-mqi-checker[gui]` 提示 |
| 已装 PySide6 | `rmqc gui --probe` | **0** |
| 已装 PySide6 | `rmqc gui` | 进事件循环，返回 `app.exec()` 的码 |

`--probe` 是交付探针：建主窗口 → 数七页签 → 跑一次 `version` 转发 → **逐页触发内核**
（每页都必须拿到输出）→ 不进事件循环直接退出。因此可在无显示环境、CI、
以及打包后的 exe 上常驻执行；探针内部 `setdefault("QT_QPA_PLATFORM", "offscreen")`。

桌面壳测试分两半：结构/argv/转发对账**不需要 Qt**（零 GUI 依赖的机器也能验），
真建窗口的 4 条标 `@pytest.mark.gui`（缺 PySide6 时声明式跳过并写明安装来源，不是静默跳过）。

## 三、打包（PyInstaller onedir 双 exe）

### 3.1 spec 的结构（`packaging/rmqc.spec`）

一次构建产出 `rmqc.exe`（控制台，等价 `rmqc` CLI）+ `rmqc-gui.exe`（windowed，等价 `rmqc gui`），
共用同一份 `_internal`（两次 Analysis + 两个 `EXE(exclude_binaries=True)` + 一个 COLLECT）。
入口是 `packaging/entry_cli.py` / `entry_gui.py` 两个薄壳，只调包里已有的 `main()`。

`datas` **逐条列出**（不整目录一把梭），并在构建期用 `glob` 与仓库现状对账——
少列/多列都在打包阶段炸，而不是留到交付后：

| 白名单条目 | 份数 | 包内落点 |
|---|---|---|
| `data/raw/<路线>-<年度>.csv` | 12 | `data/raw` |
| `data/raw/manifest.json` | 1 | `data/raw` |
| `data/truth/<路线>-<年度>.truth.csv` | 12 | `data/truth` |
| `data/README.md`（既是数据台账也是 `find_data_dir()` 认的目录标记） | 1 | `data` |
| `src/road_mqi_checker/rulesets/*.json`（内置规则集） | 1 | `road_mqi_checker/rulesets` |

**`tests/` 与 `tests/fixtures/` 一条都不进包**（常驻红线，见 §3.3）。
`excludes` 排掉 numpy / scipy / pandas / matplotlib / PIL / tkinter / PyQt / IPython 等
本项目内核零依赖却可能被间接拖进来的大件，以及 `PySide6.QtWebEngineCore`。
命令体里的惰性导入显式登记 `hiddenimports`，不靠模块图静态分析碰运气。

### 3.2 冻结态的数据目录

`data_paths.find_data_dir()` 五级优先级：显式参数 > `RMQC_DATA_DIR` > **`sys._MEIPASS/data`** >
exe 目录 `_internal/data` > 从 cwd 上溯。PyInstaller 6 的 onedir 布局让第 3 级命中 `_internal/data`，
实测（`verify_build.py` 第 5 步，在中立空目录跑）：

```
selfcheck 报告 data_dir = <dist>/rmqc/_internal/data   frozen=True
```

**验证必须在仓库树外的中立目录跑**（如 `%LOCALAPPDATA%\Temp`）：在仓库树内跑会命中仓库 `data/`，
"内嵌数据"就验了个寂寞。另外 `bench generate` 在冻结态把缺省落点改成**当前工作目录**
（不是包内副本），否则 exe 会改写自己的包，"内嵌数据与仓库逐份一致"这条红线当场失效。

### 3.3 构建后递归红线断言（`packaging/verify_build.py`，五类）

| # | 断言 | 实测（2026-10-07，`dist/rmqc`） |
|---|---|---|
| 1 | 内嵌数据与仓库**逐份 sha256 对账**，且不许有多余文件 | 期望 26 份（raw 12 + manifest 1 + truth 12 + README 1），**全部一致，无多余**；`data/raw` 13 份、`data/truth` 12 份与白名单逐条吻合 |
| 2 | 载荷无夹具字样 | 递归扫 `.json/.csv/.txt/.md` 26 份，`fixture` 命中 **0 处**（台账文档 `data/README.md` 按既有口径豁免，它描述的是机制名称） |
| 3 | 无真实形态标识符 | 复用 `privacy.PATTERNS` 反查：route 形态 token 185 个、6 位码 139 个、手机号 0 个，**越界 0 个** |
| 4 | 无标准全文 | 全包 `.pdf/.doc/.docx` **0 个**；交付文本载荷最大单文件 18645 B（`data/README.md`），>200KB **0 份** |
| 5 | exe 自带数据可用 | 中立空目录里 `rmqc.exe --json selfcheck` 的 `data_dir` 指向包内 `_internal/data` 且 `frozen=True` |

回执：`.tmp_m6/verify_build.log`（本机 scratch，收尾不删）。包体积约 **115 MB**（`rmqc-gui.exe` 带 PySide6）。

### 3.4 打包态的基准评测按设计落 3（且必须在仓库外量）

可执行包里没有 `tests/fixtures/` ⇒ `rmqc bench run` 的夹具通路 8 行如实报**不可用**，
门禁落 **3**（`GATE_PRECEDENCE` 里"不可用"这一档）；内置包通路照常出 16 行结构。
实测（把 `dist/rmqc/` 整包拷到 `%LOCALAPPDATA%\Temp` 下的空目录再跑，即用户机器的形态）：

```
gate=3  triggered_by=不可用
by_state  达标 3 / 不可判 5 / 不可用 8 / 未达标 0
fixture unavailable_reason = 夹具包（m4-fixture-asphalt.json / pci-fixture-cement.json）不在通路上，
                             数值通路无法建立 ⇒ 本通路指标不可用
```

这条红线是**双向**的：夹具值绝不随包发布（`verify_build.py` 第 2 步扫包内载荷 0 命中），
同时打包态的评测也绝不因为"包旁边碰巧有测试树"就冒充数值通路。
量这条时必须把包**拷出仓库再跑**——开发机上 `dist/` 就长在仓库里，
`evaluation.fixture_dir_candidates` 的"包源树上溯"分支会从 `_internal` 一路走到仓库根并找到
`tests/fixtures/`，此时门禁是 **0**（实测如此），量出来的就不是用户形态。
若希望 exe 也能报夹具通路，只能加显式参数由用户指向测试树，绝不随包发布夹具。

## 五、本机踩过的坑（写给下一棒）

- `.rels` 里不要写 `Override`（那是 `[Content_Types].xml` 的东西）；`ZipInfo` 要显式给
  `date_time` 与 `compress_type=8`，否则不同 zip 实现会塞 extra 字段，逐字节一致当场破。
- Word 规范：`<w:tbl>` 之后必须跟一个空段，否则相邻两张表会被合并成一张；body 末尾要有 `sectPr`。
- docx 文本抽取做断言时，正则要写 `<w:t(?:\s[^>]*)?>`——写 `<w:t[^>]*>` 会连 `<w:tbl>`
  `<w:tc>` `<w:tr>` 一起匹配上，取出来的"文本"其实是整段 XML。
- 冻结态 `bench generate` 的缺省落点必须避开包内副本（§3.2）。
- **构建通道连崩先清全局 pyc**：`Fatal Python error: tok_backup` 与 `TypeError: required field "value" missing from Attribute` 都出在 PyInstaller 的扫描/tokenizer 层，与项目代码零关联。本机实测：清掉两个系统 Python 下 **295 个 `__pycache__`**（含 `site-packages`）后构建一次过；脚本另加两道保险——`build` 连崩时换系统 `py -3.12` 通道，以及 venv 的 `ensurepip` 崩时改 `--without-pip` + 手工 `ensurepip`。
- **一键脚本必须快速失败**：venv 没建起来时 `python` 会静默落到 Microsoft Store 别名（rc=49），随后几十步全是 127 —— 那种回执毫无意义。现在 venv 之后立刻核对 `sys.executable` 是否在 `.venv` 里，不在就中止。
- 桌面壳测试要分"不需要 Qt"与"需要 Qt"两半，否则零 GUI 依赖的机器（CI、干净 venv）
  连页签结构都验不到；`--probe` 里逐页触发内核时，页面必填项留空会产生 argparse 口径的 2，
  所以探针判的是"每页都拿到输出了"，不是"每页都成功出数"。
