# 题目：公路技术状况评定与养护决策支持工具

> **性质**：模拟赛题定位，不参赛 —— 目标是发 GitHub 的独立开源桌面工具题
> **目标产出**：仓库 `road-mqi-checker`（本地目录 `10-7-road-mqi-checker`），Windows 免安装桌面 exe + 全离线内核
> **版本史**：v1（2026-10-07）定稿 —— 首期锁定"路面 PCI 评定 + MQI 汇总 + 年对比"，路基桥隧分项留扩展
> **定位宣言**：它管的是一条路**每年的检测账**：扣分表内置、路段台账持久、MQI 与分项指标可复算、评分变化能追到具体破损项。聊天框答不出"这段 4.2 公里今年比去年低 6 分是 Which 几处坑槽扣掉的、按规则该排小修还是中修"——因为它没有路段台账，也没有可复算的扣分表。

---

## 一、介绍

### 1.1 痛点（真实、可举证）

公路养护管理的基本制度是**每年进行路况检测评定，用 MQI 及其分项指标决定养护安排**。评定依据是《公路技术状况评定标准》JTG 5210-2018（编号与名称多源一致，公告号与实施日期待核对，见 data/README）。实际作业链条上的断点：

1. **扣分表复杂，人工与 Excel 都容易算错**：路面破损按类型、程度、量纲分别换算扣分比率，再叠加行驶质量（RQI）、车辙、抗滑等分项合成 PCI，最后按里程加权成路线 MQI。多表联查 + 加权，Excel 模板极易出现"同一套数据两次算分不同"；
2. **检测数据与路段台账对不上**：路段桩号断开、重叠、年度间路段划分变了，导致跨年评分不可比 —— 这是养护计划编制里最常见的数据问题；
3. **年对比与优先序没有工具**：谁先修、修什么等级，靠人工拍序，缺少可复核的排序依据；
4. **商业/内部系统封闭**：各省份多用检测车配套的内部软件出报告，评定过程不可复算、不可自行验证。

### 1.2 开源空白

GitHub 检索（2026-10-07，`gh search repos`）："resilient modulus pavement PCI" 0 条；中文"公路 技术状况" 仅命中 `kekepepe/Intelligent-Road-Defect-Detection-System`(1★，病害图像识别方向，非评定计算)。现状是**标准 PDF + 各省检测车封闭软件 + Excel 模板**，没有"扣分表可数字化、逐条挂条款号、带可复现基准"的离线开源工具。

## 二、任务要求（首期 5 个模块，其余留扩展）

> **通用确定性纪律**：扣分比率表、分项指标权重、分级阈值三类系数，每一格都要登记来源（标准条款号 / 地方细则 / 用户自定）。**未完成原文核对的系数一律不得进入评定路径**；该路段/该指标输出"待定值"，不得给出评分。

### 模块 1：路线—路段台账与检测数据导入

- **输入**：路线基本信息（路线编号、行政等级、技术等级、起止桩号）、路段划分表、年度检测数据（路面破损调查表：破损类型/程度/数量；RQI、车辙、抗滑等实测指标；桩号区间）。
- **输出**：SQLite 台账（路线 → 路段 → 年度检测记录）+ 导入回执（入库/拒入行数与原因）。
- **引擎**：确定性校验。桩号连续性（悬空段、重叠段）、路段长度与路线里程闭合差、破损类型字典合法性、单位一致性、重复导入去重、跨年度路段划分变更识别（新增/消失/合并/拆分）。
- **要点**：**跨年度划分不一致必须显式标记为"不可比"**，不得静默按比例摊分。

### 模块 2：路面技术状况评定引擎（PCI，本题核心）

- **输入**：模块 1 台账 + versioned 扣分规则集。
- **输出**：逐路段 PCI 分项得分与合成得分，每个得分项可展开到"哪一条破损/哪个实测指标扣了多少分"。
- **引擎**：规则优先，纯算术，无概率、无模型。
  - 破损 → 扣分比率换算（按类型、程度、量纲分别处理，沥青与水泥混凝土路面两套表）；
  - 分项指标合成 PCI（各分项权重与组合关系按标准条款实现，逐条挂条款号）；
  - 结果可复算 —— 同一台账同一规则集，任何一次重跑必须得到完全一致的分数（浮点比较用固定舍入规则）。
- **首期范围红线**：**只做路面 PCI（沥青 + 水泥混凝土两类）与 MQI 汇总所需最小集**。路基、桥梁遂道、沿线设施分项指标留扩展 —— 它们各自另有评定标准，一次做完必然范围失控。

### 模块 3：MQI 汇总与技术状况等级

- **输入**：PCI 结果 + 首期可用的分项（其余以"未评定"参与汇总策略）。
- **输出**：路段/路线/路网三级 MQI（按里程加权）、技术状况等级（优/良/中/次/差，分级阈值挂条款号）、"未评定分项导致汇总口径受限"的明确声明。
- **引擎**：加权汇总 + 分级判定；三级汇总口径必须一致可复算（路段→路线→路网同一套权重来源）。
- **纪律**：分项不全时，**不得**输出"MQI 完整评定值"冒充全口径结果，只能输出注明口径的部分指标值。

### 模块 4：养护对策规则链与年对比

- **输入**：多年度评定结果 + 对策规则集（触发条件→建议养护工程类别与规模档）。
- **输出**：路段级养护需求判定清单、路线优先序排序表、年度对比表（评分变化、劣化速率、变化贡献项）、可导出的建议计划表。
- **引擎**：规则链，每条规则写"IF 条件（含指标与阈值）→ THEN 建议类别"，并挂条款号；排序键可配置但必须确定（同分排序用固定次级键，禁止随机）。
- **要点**：每条建议必须能回答"由哪个指标的哪一次变化触发"——这是"年对比"模块的价值所在，也是聊天框完全做不到的（需要多年台账）。

### 模块 5：内置基准与合成数据生成器

- **合成生成器**：按典型损坏模式生成检测数据（正常老化、局部突发损坏、数据录入异常如负值/超范围/单位错、路段划分变更），并给出真值：`路段 → PCI/MQI/等级/应触发的对策类别`。
- **基准来源**：若标准原文含算例，录入为黄金用例（逐格核对后入库，未核对不入库）；自算用例须给出可复算的推导过程。
- **评测指标**：评分复算误差 = 0（同数据同规则集重跑一致）、等级判定准确率、扣分贡献项排序一致性、数据异常识别召回与误报。
- **纪律**：基准须干净环境一键复现，明确依赖清单，不依赖网络与外部模型。

### 明确不做（首期排除）

路面结构强度设计与弯沉评定、养护工程量计算与定额计价（属造价产品线）、病害图像识别（不可确定性评测）、GIS 大屏与可视化驾驶舱、桥梁隧道专项评定、检测车原始信号处理。

## 六、边界与非目标

1. **辅助定位，不是决策工具**：输出的是"按已核对规则算出的评定值与规则链建议"，**不替代养护科学决策、不替代正式评定报告**；导出文件固定免责声明。
2. **不做设计与造价**：不输出结构厚度、材料用量、工程概算类结论。
3. **隐私与数据红线**：全部本地运行、不联网、不上传；示例数据用虚构路线编号（S99/X99/Y999 类）、虚构行政代码（990000 类）、假手机号段（19900000000 式）、假 DOI（`10.9999/`），合成数据文件带 `SYNTHETIC` 标记。
4. **版权红线**：不提交标准全文与扫描件；仓库只放自行整理的条款摘录笔记（已在 `.gitignore` 排除 `data/standards/*.pdf`）。
5. **结论纪律**：未核对系数不进评定路径；分项不全不冒充完整 MQI；跨年度划分不可比时不得给"变化率"结论；任何异常只能报"应核实"，不得写成"已确认"。
6. **品牌隔离**：本项目与其他工程类工具（结构验算、支架验算、加固验算、施工安全研判、招投标合规等）无代码与文档引用关系，互不提及对方业务；方法论同源但仓库独立。
7. **范围红线**：首期只做 5 个模块；桥隧分项、图像识别、大屏一律留扩展，不进主线。
