# 评定与汇总算法说明（M2 交付 PCI 部分，M4 补汇总与分级部分）

> 本文件写的是**算法与口径**：换算式形态、系数字段契约、舍入、拒算条件、贡献展开的排序键。
> 词汇与判据的单点定义仍在代码里（`pci/engine.py`、`pci/trace.py`、`ledger/checks.py`、`ruleset/status.py`），
> 文档只引用不另写一套；字段口径见 `plan/03-数据字典与合成数据.md`。
> 本文**不出现任何规范阈值数字**：所有阈值/比率/权重都由规则集给出，未核对（`pending`/`located`）不进计算。

---

## 一、范围与输入输出

| 项 | 内容 |
|---|---|
| 评定对象 | 一个"路段 × 年度"（`segment` 主键 `(segment_id, year)`） |
| 输入 | 该路段的几何属性（长度、车道数、路面宽、板块总数）+ 该年度检测记录（实测指标）+ 该年度破损调查行 |
| 规则集 | 一个 versioned 包（`ruleset.loader.select_ruleset` 选取，`pci_weight.<surface>` 等六格支配计算） |
| 输出 | `results.PciResult`：分项得分、合成得分 PCI、等级、扣分合计、扣分贡献清单 |
| 命令面 | `rmqc assess --year <YYYY> [--segment <ID>]`；`--json` 出结构（M4 汇总与 M6 GUI 消费同一结构） |
| 退出码 | 全部 `ok` → 0；存在 `blocked`/`partial`/`uncomparable` → 1（降级完成）；该年度台账没有路段行 → 2 |

首期只做**沥青 + 水泥混凝土两种路面的 PCI**。路基、桥隧、沿线设施不在本模块（`plan/01` 非目标）。

## 二、换算式（本实现口径）

四条算式，每一条的**数字全部来自规则集那一格系数**，算式形态本身是实现约定：

### 2.1 破损分项扣分

一条破损调查记录的扣分：

```
扣分(行) = 扣分比率(破损类型, 程度) × 该破损占评定单元的几何比例 × 满分
几何比例 = 数量 / 分母，分母由该路段自带数据算出：
    extent=area   → 路段长度 × 路段宽度        （m2）
    extent=length → 路段长度 × 车道数          （m，沿行车方向累计）
    extent=panel  → 该路段板块总数             （块）
破损分项得分 = max(0, 满分 − Σ 各条扣分)
```

- 分母只用台账自带的几何事实（`plan/03` §二 的三类量纲），**不引用任何规范阈值**；
- 比率格 `deduct_ratio.<surface>_distress` 的 `values` 形态：`{"ratios": {破损类型: {程度: 比率}}}`，
  比率是 0～1 的无量纲数；缺该类型或缺该程度 → 拒算（不"按邻近程度代一下"）；
- 数量超过分母（几何比例 > 1）→ 拒算：占比失去意义，扣分也就失去意义；
- `满分 = 100.0`、`下限 = 0`（`engine.SCORE_SCALE` / `SCORE_FLOOR`）是百分制的**量程边界**，
  与 `PCI_DECIMALS` 同类的结构常量，不是规范阈值。规范里的分级边界、容差一律不得写在这里。

### 2.2 实测指标分项

| 分项 | 读取的检测列 | 换算 | 系数字段 |
|---|---|---|---|
| 行驶质量 | `rqi` | 直接取实测指数（指数本身定义域 0～100，见 `models.INDICATOR_DOMAIN`） | `pci_component.ride_quality` → `{"weight": w}` |
| 车辙 | `rut_depth_mm` | `满分 × (zero − 实测) / (zero − ideal)`，截断到量程内 | `pci_component.rutting` → `{"weight": w, "ideal_mm": a, "zero_mm": b}` |
| 抗滑 | `skid_indicator` | `满分 × (实测 − zero) / (ideal − zero)`，截断到量程内 | `pci_component.skid_resistance` → `{"weight": w, "zero_value": a, "ideal_value": b}` |

- 端点 `ideal` / `zero` 由规则集登记，**引擎不猜**：缺字段或 `zero ≤ ideal`（换算方向不成立）一律拒算；
- 实测值先过该指标自身定义域，超域即拒算（"这条记录不可能是真值"，`plan/03` §二）；
- 抗滑按 `skid_indicator_kind`（SFC/BPN）取定义域，量纲未登记 → 拒算。

### 2.3 PCI 合成

```
PCI = Σ(权重 × 分项得分) / Σ(参与分项的权重)
```

- 权重来自 `pci_weight.<surface>` → `{"weights": {"distress": …, "ride_quality": …, "rutting": …, "skid_resistance": …}}`；
  权重和不必是 100，公式按参与分项的权重和归一；
- 出现未认定的分项名（拼错的键）→ 拒算，不静默忽略；权重非正 → 拒算；
- **缺测分项不参与加权**：该分项对应的检测列是 `NULL` 时，整体转 `partial` 并写口径声明
  （`scope_note` 点名"哪个分项因哪一列缺测被剔除"），绝不把缺测当 0 算，也绝不"平均一下"补一个值。

### 2.4 等级判定

```
grade_threshold.pci → {"boundary": "lower_inclusive" | "lower_exclusive",
                       "bands": [{"grade": 名称, "min": 下界}, …]}
```

- 档位名由规则集给（不硬编码"优/良/中/次/差"）；
- **含界与否由 `boundary` 显式登记**：同一个 PCI 在两种登记下必须给出不同等级
  （`tests/test_m2_pci_engine.py::test_grade_boundary_openness_comes_from_the_ruleset` 锁住这条）；
- 下界有重复值（档位无法唯一）→ 拒算。

## 三、舍入口径

| 项 | 口径 | 落点 |
|---|---|---|
| 得分与扣分值 | 保留 1 位小数（`PCI_DECIMALS`），十进制**半值向上**（`ROUND_HALF_UP`），不用 Python `round` 的银行家舍入 | `pci.engine.quantize` |
| 贡献占比 `share` | 保留 3 位小数（`SHARE_DECIMALS`）：扣分保留 1 位会把 0.016 这类占比抹成 0.0 | `pci.engine.quantize(..., SHARE_DECIMALS)` |
| 中间量 | 不逐步舍入：全部用浮点算到最后一步再舍入，避免"舍入两次"的漂移 | `compute_pci` |
| 等级判定 | 用**舍入后的 PCI** 查档（报告里显示的分与下的等级必须自洽） | `_grade(quantize(pci), …)` |

`quantize(87.75, 1) == 87.8`、`quantize(0.05, 1) == 0.1`、`quantize(-0.05, 1) == -0.1`（有测试）。

## 四、拒算条件（`blocked` 的全部入口）

`blocked` 的结果对象**数值字段全空**（PCI、扣分合计、分项得分字典、等级、贡献清单），由
`results.check_contract()` 强制；引擎返回前自己调用一次，所以"绕过契约"这条路在代码层就不存在。

| # | 类别 | 具体条件 | 拒算原因里说什么 |
|---|---|---|---|
| 1 | 系数门 | 六格必需系数（`surface_table_keys`）任一未登记、或生效档位是 `pending`/`located` | 逐格点名（`ruleset.status.blocked_reason` 的固定措辞），一次报全 |
| 2 | 系数门 | 系数可算但 `basis` 里没有任何条款号 | "未登记条款号，扣分不可追溯" |
| 3 | 路面类型 | 类型不在 `asphalt`/`cement` 里 | 首期不支持 |
| 4 | 检测记录 | 该路段该年度没有 `survey` 行 | 实测指标无从取值 |
| 5 | 数据门 | 破损类型不在该路面字典 / 程度不在档位 / 量纲与字典不符 | 指名类型、程度、量纲与台账行号 |
| 6 | 数据门 | 数量为负、非数值、或超过几何上界 | 同上 |
| 7 | 数据门 | 换算分母算不出（缺车道数/宽度/板块总数） | 点名缺哪个属性 |
| 8 | 数据门 | 实测指标超出自身定义域 | 点名检测列与定义域 |
| 9 | 系数契约 | 比率不在 0～1、换算端点缺失或方向矛盾、权重表有未认定分项、分级边界未登记开闭口径 | 指名系数 key 与字段 |
| 10 | 检出项门 | M1 校验层对该路段该年度有 `found` 结论且属于 `BLOCKING_CHECK_KINDS`（破损字典 / 量纲一致 / 负值与超范围 / 重复导入） | "台账含 M1 检出项（类别）：detail" |

**两层判据不分家也不合并**：第 5–8 条与第 10 条是同一件事的两个入口 —— 台账通路（CLI/GUI）走第 10 条，
即直接复用了 `ledger.checks` 的结论；生成器的真值通路走第 5–8 条（内存行还在校验层之外）。
两条通路共用同一个换算核 `compute_pci`，所以对同一份数据给同一个结论（见 §六）。

不进拒算清单的检出项：桩号悬空/重叠、长度闭合差、跨年划分变更。它们让**里程账与跨年可比性**失效，
不让"这一段今年扣了多少分"失去意义 —— 评定照常出数，不可比标记由 M4 的年对比处理。

## 五、扣分贡献展开

`pci.trace.expand_contributions(PciResult)` → 逐条贡献行，列序即 `TRACE_COLUMNS`：

```
segment_id, year, source_kind, distress_type, severity, quantity, quantity_unit,
coefficient_key, clause, deducted_points, share, source_row_no
```

- **贡献值可加**：每条贡献折到 PCI 尺度 `扣分 = 分项内扣分 × 该分项权重 / 参与权重和`，
  于是 `Σ 贡献 = 100 − PCI`（未舍入前恒等；显示值允许每位 0.05 的舍入残差，测试按此上界断言）；
- 破损类贡献：一条破损调查记录一行，必挂 `coefficient_key` + `clause` + **`source_row_no`**；
  `source_row_no` 是台账 `distress.source_row_no`，其编号语义 = 原始检测表的数据行序
  （`ledger.importer.read_table` 跳过标记行与表头后的第 N 行），所以展开视图能一路指回用户手里那份 CSV 的那一行；
- 实测指标类贡献：分项一行（`source_kind=measured_indicator`），回指它的系数格与条款，没有台账行号可指；
- **排序键固定**：`deducted_points` 降序为主键，同分时按 `source_kind → distress_type → severity →
  quantity → source_row_no → coefficient_key` 逐个升序比较（空值排后）。禁止依赖 set/dict 迭代顺序
  或 SQLite 返回顺序；测试用逐位旋转 + 反序输入验证重排不变；
- `blocked` 对象展开为**空清单**：没有扣分可展开，`trace.report_lines` 只出拒算原因，
  不会显示"扣 0 分"这种看起来像结论的行。

## 六、两条通路，同一个内核

```
rmqc assess ──┐
              ├─→ pci.engine.compute_pci(段字典, 规则集, 检出项) ─→ PciResult ─→ pci.trace
生成器真值 ───┘        ↑ 从内存行拼段字典（取已落盘的文本值）
```

- 台账通路：`load_segment_input(conn, …)` 从 SQLite 拼段字典 + `blocking_findings(conn, year)` 取检出项；
- 真值通路：`bench.generator._probe_input()` 从**即将写入那份 CSV 的文本值**拼同形字典，
  并按导入层 `R008` 的同一套身份列去掉文件内重复行 —— 真值描述的是"进了台账的那本账"；
- 数值真值唯一入口 `generator._numeric_truth_probe` → `pci.engine.compute_pci`：
  生成器里**没有第二套扣分公式**，所以不会出现"真值一份公式、引擎另一份公式"的假对账；
- 系数门仍在生成器一侧先查 `TRUTH_GOVERNING_KEYS`（与 `surface_table_keys` 同一批格子，有测试对账），
  未核对 → 真值仍是 `pending:coeff=…` 令牌；系数齐了但引擎因数据拒算 → 真值写
  `pending:engine=pci.engine.blocked`，**同样不出数**。

## 七、M2 出口实测（夹具规则集通路）

内置包 15 格全 `pending`，所以交付面（`data/` + 内置规则集）上所有对象一律 `blocked`；
数值通路只在 `tests/fixtures/` 的夹具包里验证（夹具值不是规范事实，红线测试禁止它进交付面）。
这不是"异常数据拒算没测"：内置包下所有对象本来就因系数被拒，无法把"因为数据异常被拒"与
"因为系数未核对被拒"区分开；夹具包把系数门打开后，同一份演示数据里 36 个对象出数、
6 个异常对象单独 blocked，两类拒算才各自有可断言的证据（`test_m2_assess.py` 两类都覆盖，
其中内置包那类由 `test_assess_with_builtin_ruleset_degrades_to_exit_one` 守住）。

| 指标 | 实测 | 口径 |
|---|---|---|
| 评分复算误差 | **0** | 42 个"路段×年度"对象，真值列与台账通路逐字段比对：`pci_truth` / `grade_truth` 全等，0 处不符；另有两次进程冷启动 `assess --json` 输出逐字节一致 |
| 出数分布 | ok 28 / partial 8 / blocked 6 | 8 个 partial 全是水泥路段（演示数据不测车辙，缺测不参与加权）；6 个 blocked 正是 M1 注入的负值×2、超范围×2、单位错×2 对象 |

### 7.1 黄金用例（夹具数，不是规范数）

**沥青** `SYN-G1`：长 1000 m、车道数 2、宽 7.5 m；`rqi=85.0`、`rut_depth_mm=6.0`、抗滑 `SFC=50.0`；
破损 3 条（夹具比率：坑槽/重 0.20、纵向裂缝/中 0.04、网状裂缝/轻 0.05；面积分母 7500、长度分母 2000）：

```
扣分 = 0.20×150/7500×100 + 0.04×100/2000×100 + 0.05×75/7500×100 = 0.40 + 0.20 + 0.05 = 0.65
破损分项 99.35；车辙 100×(18−6)/(18−2) = 75.0；抗滑 100×(50−20)/(60−20) = 75.0
权重 40/30/15/15 → PCI = (40×99.35 + 30×85 + 15×75 + 15×75)/100 = 8774/100 = 87.74 → 87.7
等级（夹具档位 lower_inclusive，良 ≥ 80.25）→ 良；扣分合计 12.26 → 12.3
贡献（折到 PCI 尺度，破损分项权重 40/100）：0.16 / 0.08 / 0.02 / 行驶质量 4.5 / 车辙 3.75 / 抗滑 3.75，合计 12.26
```

**水泥** `SYN-G2`：长 1000 m、车道数 2、板块总数 100；`rqi=90.0`、`rut_depth_mm` 缺测、抗滑 `BPN=30.0`；
破损 2 条（夹具比率：破碎板/重 0.35、裂缝/轻 0.02；板数分母 100、长度分母 2000）：

```
扣分 = 0.35×5/100×100 + 0.02×200/2000×100 = 1.75 + 0.20 = 1.95 → 破损分项 98.05
抗滑 100×(30−20)/(60−20) = 25.0；车辙缺测 → 不参与加权，整体 partial
权重 45/25/15/15，参与三项权重和 85 → PCI = (45×98.05 + 25×90 + 15×25)/85 = 82.79117… → 82.8
等级（夹具档位 lower_exclusive，良 > 78.5）→ 良
```
