## 三、用户自定口径登记表

这一节登记**不来自规范原文**、由本项目自定并显式生效的口径。它们同样走 schema 门
（`status=verified` 必须补齐 `clause/channel/verified_at/locator` 四件套，否则拒绝整包加载），
但依据是"项目自定 + 理由写在案"，不是"官方原文"。

### 用户自定口径第 1 号：闭合差容差 `tolerance.length_closure = 1 m`

- **落点**：`base-jtg5210-2018.json` 的 `tolerance.length_closure`，`values = {"meters": 1}`；
  消费方 `ledger/checks.py::check_length_closure`。
- **口径**：路段长度和与路线声明里程的闭合差，绝对值 ≤ 1 m 视为不报；> 1 m 报检出
  `R004_CLOSURE_EXCEEDED`；该格退回 pending 时**只报实测差值、判"未判定"**。
- **为什么是 1 m**：桩号按整米登记（`K12+300` 形态，`ledger/models.py::parse_stake` 只产整数米），
  路段长度与路线里程都由整米桩号相减得到 ⇒ 口径一致的账闭合差必为 0。
  放宽到 1 m 只为吸收路段划分时末段取整的一米差；任何更大的差都是真实的账实不符，
  正是这道题要抓的东西（演示数据里注入的悬空/重叠造成的 −200 / +100 m 全部转为检出）。
- **为什么不是 0 m**：闭合差为 0 的格子本来就不报（`test_zero_closure_is_not_reported`），
  取 0 会让"划分取整差 1 m"这种无害情形变成检出，把噪声写进导入回执。
- **可改性**：改这一格**不需要规范原文**，但它会改变校验结论计数
  （`plan/03` §五 的"27 条 = 27 检出 + 0 未判定"随之变化），改后要同步那处数字与两条同名门。
- **纪律**：不允许在代码里硬编码默认容差；用户自定也必须显式登记在本节与依据台账第 9 行。

## 四、水泥路面分项要不要"车辙"——本轮结论：无法按原文确认，保持待核对

内置包 `pci_component.rutting` 的 note 要求"水泥路面是否参与该分项需按原文确认"。

- **本轮结论**：**无法确认**，因为原文条款表不可得（§一）。所以：
  1. `pci_weight.cement` 仍是 `pending`、`values = null`，**分项集合尚未定案** ——
     "从 weights 里去掉 `rutting` 键"这个动作只能在 `pci_weight.cement` 转 verified 那一刻一起做，
     现在没有 weights 可去；
  2. **不改代码**：引擎按 `pci_weight.<surface>` 的 `weights` 键决定参与分项，未知分项直接拒算
     （`plan/05` §二），去掉键即不参与，无需新增开关；
  3. 已生效的通路证据是夹具：`tests/fixtures/pci-fixture-cement.json` 里水泥**含**车辙分项
     （40/25/15/15 形态），但这只证明"通路支持这种登记形态"，**不代表规范事实**；
     同目录另一条测试用"水泥不测车辙"的中间态（M2 实测 8 个水泥对象转 `partial` 带口径声明）
     证明"缺该分项"这条通路同样通。两种形态都能算，选哪种**等证据**。
- **留给下一棒的判据**：拿到原文后看水泥 PCI 分项表里有没有车辙（或"车辙"是否只对沥青路面列出）。
  有 → `pci_weight.cement.weights` 保留 `rutting`；没有 → 去掉该键，并把条款号/表号回填本表第 7 行
  与 `data/README.md` §一 第 1 行。
- 演示数据的 `rut_depth_mm` 列对水泥路段本就留空（`plan/03` §二），所以"去掉该键"不会与数据形态冲突。

  | `jtyst.shaanxi.gov.cn/glj/`（陕西省公路局栏目页） | 200 | 栏目列表，无省级扣分表 |
  | `jtt.shandong.gov.cn`、`jtyst.henan.gov.cn` | 200 | 厅站首页，无省级扣分表 |
  | `jtt.hubei.gov.cn` | 412 | 反爬拦截 |
  | 粤 / 苏 / 浙 / 川 厅站 | 000 | 连接失败 |

  取到的都是首页与栏目页，**没有任何一份能在官方页里读到"与 JTG 5210-2018 不同的扣分比率/权重/阈值"**；
  站内检索接口本身也未取得可用入口。按纪律不采信文档分享站上的"某省细则"转载。
- 因此**不编造省份包**：内置包的 `applies_to.province` 仍是 `*`，`RMQC_RULESET_DIR` 覆盖通路
  只作为"用户自定规则"的载体存在（用户放进去的包同样过 schema 门与四件套要求）。
- 一旦拿到省级官方原文，登记顺序：先在 `data/README.md` §一 加行（行号即 `register_ref`），
  再在仓库外建省级包，用 `RMQC_RULESET_DIR` 指向它，最后由 `ruleset show` 逐格显示差异。

## 七、下一棒（M4）要用的事实

1. 分级阈值两格（`grade_threshold.pci` / `.mqi`）**未生效** ⇒ M4 的 MQI 汇总与等级判定
   在内置包下必须同样 `blocked`，不得为"看到数字"造阈值；M4 的数值通路与 M2 一样用夹具包自证。
2. `mqi_weight.pavement` 未生效，且首期只有路面分项 ⇒ 汇总口径必须标"部分口径"，
   不得套用完整 MQI 的分级表述（`data/README.md` §一 第 13 行的 note 已写死这条）。
3. `pci.engine.assess_year` 返回的 `List[PciResult]` 就是 `mqi.engine.aggregate_*` 与
   `strategy.compare.compare_years` 的 `pci_results` 入参形态（`HANDOFF-M3.md` §一 已交接），
   M4 不要另起取数路径。
4. 想让用户看到真实数字，唯一入口是**拿到 JTG 5210-2018 正式电子原文或纸质原文**后逐格核对：
   一次改一格的四件套（status + values + basis），先过 `ruleset show` 的 schema 门，
   再按 `test_ruleset_builtin.py` 的形状门填形状，最后 `rmqc bench generate --force` 重生演示数据并单独提交。
