# 06 · 基准与评测（M5 交付）

> 本文只**引用**代码里的判据与实测数，不另立第二套口径：指标词汇与分子分母定义在
> `src/road_mqi_checker/bench/evaluation.py`，出数判据在 `bench/generator.py` 的必需格函数里，
> 算法在 `plan/05`。文档里的每个数字都来自 `rmqc bench run` 或本文 §六 的复现命令（2026-10-07，
> py3.8.8 与 py3.12 双通道实测）。

## 一、基准要回答什么

这道题的评测必须同时回答两个**不同**的问题，混起来就是自欺：

1. **交付面现在能不能出数？** 内置规则集 15 格里只有 1 格生效（用户自定的闭合差容差），
   规范来源的 14 格仍是 `pending`（官方原文不可得，`plan/04`）。必需格没齐 ⇒
   `assess` / `aggregate` / 对策 / 年对比 四条路径全部拒算，于是**任何"准确率/误差"类指标
   在内置包通路上的分母都是 0**。分母为 0 叫"不可判"，不叫达标，也不叫不可用。
2. **算术与口径自洽吗？** 用 `tests/fixtures/` 里的夹具档系数（值全部是虚构数）把同一条内核
   跑通，复算真值列、重排贡献清单、逐位比对三级汇总。这条路能出数，但**数字只说明
   "算法与口径一致"，不说明"规范口径下算对了"**——夹具值刻意避开任何真实规范数字。

因此每条指标按 **通路 × 指标** 出一行：`PATH_ORDER = (builtin, fixture)` × `METRICS`（8 条）= **16 行**，
每行显式带 `分子 / 分母 / 状态 / 判据 / 说明 / 目标 / 退出码`。两通路各带一句诚实线
（`PATH_HONESTY`），措辞不得互相顶替。

四态与退出码：`达标 0 / 未达标 1 / 不可判（分母为 0）2 / 不可用（通路拿不到）3`
（`STATE_TO_EXIT`，单点定义，锁在 `tests/test_cli_contract.py`）。

## 二、指标定义（分子 / 分母 / 判据）

| 指标键 | 名称 | 分子 | 分母 | 判据（代码） | 目标 |
|---|---|---|---|---|---|
| `rescore_drift` | 评分复算误差 | 逐字段相符的真值格数 | 真值与台账通路**两边都出数**的真值格数（4 列 × 42 对象） | `metric_rescore_drift` + `_ledger_value`，值取最大绝对偏差（1 位，`PCI_DECIMALS`） | = 0 |
| `grade_accuracy` | 等级判定准确率 | 与独立规范等级真值相符的对象数 | 有独立规范等级真值的"路段×年度"对象数 | `metric_grade_accuracy`（分母恒 0，见 §七） | ≥ 0.95 |
| `contribution_order` | 扣分贡献项排序一致性 | 重排后展开视图逐行相同的比较次数 | 全部重排比较次数（逐位旋转 + 反序） | `metric_contribution_order` + `pci.trace.expand_list` | ≥ 0.95 |
| `aggregation_consistency` | MQI 汇总口径一致性 | 复算值 / 复算分母与引擎输出逐位相等的比对次数 | 4 年度 ×（3 路线级 + 1 路网级）×（MQI 值 + 加权里程） | `metric_aggregation_consistency`，里程由 `PathContext.route_members/year_members` 独立取数 | 三级同一分母可互相复算 |
| `change_contribution_order` | 变化贡献项排序一致性 | 重排后变化拆解逐行相同的比较次数 | 逐年对 × 两侧 ×（逐位旋转 + 反序） | `metric_change_contribution_order` + `strategy.compare.explain_change` | ≥ 0.95 |
| `anomaly_recall` | 数据异常识别召回 | 命中的注入用例数 | 真值 `injected_issue` 声明的注入用例数（格级 + 划分变更标记） | `metric_anomaly`；类别→校验项映射 = `EXPECTED_KIND_BY_ISSUE` | ≥ 0.95 |
| `anomaly_false_alarm` | 数据异常识别误报 | 未被格级注入标记的对象上的格级六类检出数 | 未被格级注入标记的"路段×年度"对象数 | `metric_anomaly`（越低越好，阈值 0） | = 0 |
| `byte_reproducible` | 产物位级一致 | 逐字节一致的文件数 | 参与比对的文件数（raw + truth + manifest，不含 `.gitkeep` 一类占位） | `metric_byte_reproducible` + `_byte_state` | 两次运行逐字节一致 |

三条纪律写在判据里，不在注释里：

- **出数判据只走必需格**：`evaluation.path_gates()` 逐路径调
  `generator.scoring_gate_pending_keys / aggregation_gate_pending_keys / action_gate_pending_keys`
  （`plan/02` §9 第 23、28、32 条）。`bench run --json` 的 `paths.builtin.path_gates`
  与 `rmqc --json selfcheck` 的 `path_gates` 必须逐路径相等（有测试断言）。
- **blocked 不从分母里悄悄摘掉**：复算误差把拒算格改报"真值令牌与台账拒算相符 n/n"，
  仍出现在同一行的说明里；变化贡献排序只统计可拆的对次，但 `uncomparable` 的数量由
  `paths.*.compare_counts` 与 `note` 一并报出。
- **每条指标都有正证与反证**：真实通路给正证（夹具包出数）与不可判反证（内置包分母 0），
  判据函数本身再用 `_ratio_state` / `_byte_state` 钉住三端（`test_m5_bench.py` 参数化覆盖 8 条指标）。

## 四、门禁语义

`evaluation.gate()` 只红于三类，其余一律放行：

| 触发 | 退出码 | 理由 |
|---|---|---|
| 存在未达标 | 1 | 数算出来了但对不上，是回归 |
| 存在不可用 | 3 | 通路本身拿不到（如打包态没有 `tests/fixtures/`），属未实现/未就位 |
| 存在**名单外**的不可判 | 2 | 分母为 0 通常意味着有对象被从通路上摘掉了 ⇒ 按数据门事故处理 |
| 只有达标 + 名单内不可判 | 0 | 今天的状态：6 行不可判全部登记在 `DECLARED_INDETERMINATE` |

- 严重度顺序 = `GATE_PRECEDENCE`（未达标 > 不可用 > 名单外不可判）。
- `STATE_TO_EXIT` 仍是**单行**映射（不可判 → 2 没有改），门禁只在其上叠加"名单内豁免"。
- 已声明不可判名单是代码常量（frozenset，6 项：内置包的复算/扣分排序/汇总/变化排序 +
  两条通路的等级准确率），不是注释——注释会被悄悄放宽，常量要改代码才生效。
- **不许为了让表格好看把不可判改成达标**：M4 之前 README 的复算误差写"达标 0"，
  那其实是夹具通路的数；M5 起分成两列，内置包那列如实写不可判。

## 五、黄金用例（可手算复核）

规则集：`evaluation.merged_fixture_ruleset()`（`m5-bench-fixture-both`，14 格全 fixture 档，
= `m4-fixture-asphalt.json` 与 `pci-fixture-cement.json` 的并集，没有新写一套夹具数）。
复算脚本与原始输出：`.tmp_verify/M5/golden.py` → `.tmp_verify/M5/golden.log`；
台账素材用 `tests/support_pci.py` 的 spec + `insert()`。以下每一步都能用计算器对上，
舍入口径是半值向上、得分与 MQI 保留 1 位（`pci.engine.quantize`）。

### 用例 1 沥青 PCI（`support_pci.ASPHALT_SPEC`，SYN-G1 / 2025）

入参：长 1000 m、车道 2、宽 7.5 m、rqi 85.0、车辙 6.0 mm、抗滑 SFC 50.0；破损 3 行。
扣分比率取夹具表 A-1：坑槽/重 0.20、纵向裂缝/中 0.04、网状裂缝/轻 0.05。

| 破损行 | 数量 | 几何分母 | 占比 | 比率 | 分项内扣分 |
|---|---|---|---|---|---|
| 坑槽 / 重 | 150.0 m² | 7.5 × 1000 = 7500.0 | 0.020000 | 0.20 | 150/7500 × 0.20 × 100 = 0.400000 |
| 纵向裂缝 / 中 | 100.0 m | 2 × 1000 = 2000.0 | 0.050000 | 0.04 | 100/2000 × 0.04 × 100 = 0.200000 |
| 网状裂缝 / 轻 | 75.0 m² | 7500.0 | 0.010000 | 0.05 | 75/7500 × 0.05 × 100 = 0.050000 |

Σ 分项内扣分 = 0.65 ⇒ 破损分项得分 = 100 − 0.65 = **99.35**（显示值 99.4）。
分项得分：`distress 99.35 / ride_quality 85.0 / rutting 75.0 / skid_resistance 75.0`。
三个实测分项的换算式（端点全部来自夹具格 `pci_component.*`，见 `plan/05` §二）：
行驶质量直取 rqi = 85.0；车辙 = (zero_mm 18 − 6) / (18 − ideal_mm 2) × 100 = 12/16 × 100 = **75.0**；
抗滑 = (50 − zero_value 20) / (ideal_value 60 − 20) × 100 = 30/40 × 100 = **75.0**。
权重 `pci_weight.asphalt = 40/30/15/15`：

PCI = 0.40 × 99.35 + 0.30 × 85.0 + 0.15 × 75.0 + 0.15 × 75.0 = 39.74 + 25.50 + 11.25 + 11.25 = **87.74 → 87.7**

引擎输出：`status=ok PCI=87.7 等级=良 扣分合计=12.3`（`grade_threshold.pci` 夹具档：良 ≥ 80.25，
`boundary=lower_inclusive`）。贡献展开（PCI 尺度）：ride_quality 4.5、rutting 3.8、skid 3.8、
坑槽 0.2、纵裂 0.1、网状 0.0 ⇒ Σ 显示值 12.4 对 100 − 87.7 = 12.3，
差 0.1 是**逐项舍入残差**，不在项间摊分（`test_m2_trace.py` 锁的就是这个残差上界）。

### 用例 2 水泥 PCI 且缺测分项（`support_pci.CEMENT_SPEC`，SYN-G2 / 2025）

入参：长 1000 m、宽 9.0 m、板数 100、rqi 90.0、**rut_depth_mm = NULL**、抗滑 BPN 30.0；破损 2 行。

| 破损行 | 数量 | 几何分母 | 占比 | 比率 | 分项内扣分 |
|---|---|---|---|---|---|
| 破碎板 / 重 | 5.0 块 | panel_count 100.0 | 0.050000 | 0.35 | 5/100 × 0.35 × 100 = 1.750000 |
| 裂缝 / 轻 | 200.0 m | 2 × 1000 = 2000.0 | 0.100000 | 0.02 | 200/2000 × 0.02 × 100 = 0.200000 |

Σ = 1.95 ⇒ 破损分项 = **98.05**；rqi → 90.0；抗滑 BPN 30 → 25.0。
车辙缺测 ⇒ **不参与加权**，权重按剩余三项归一（45/25/15 → /85）：

PCI = (45 × 98.05 + 25 × 90.0 + 15 × 25.0) / 85 = (4412.25 + 2250 + 375) / 85 = 7037.25 / 85 = **82.7911 → 82.8**

引擎输出：`status=partial PCI=82.8 等级=良`，`scope_note` 点名
"缺测分项不参与加权（rutting（缺测 rut_depth_mm）），权重按其余分项归一"。
把缺测当 0 分会得到 PCI ≈ 75.2——那正是这道题禁止的做法（§9 第 20 条）。

### 用例 3 路线级 MQI 加权（同一路线 3 个成员路段，2024 年度）

路段级 MQI（首期只有路面分项 ⇒ 一律 partial）与台账里程：
`SYN-R1 87.7 / 1000 m`、`SYN-R2 83.3 / 2000 m`、`SYN-R3 93.8 / 3000 m`。

Σ(MQI × L) = 87.7×1000 + 83.3×2000 + 93.8×3000 = 87700 + 166600 + 281400 = **535700**
ΣL = 6000 ⇒ 535700 / 6000 = 89.2833 → **89.3**

引擎输出：路线级 `mqi=89.3 weighted_length_m=6000.0 status=partial grade=None`；
路网级同为 89.3（该年度只有这一条路线）⇒ 三级同分母恒等成立。
`blocked` 成员不在这里，但在真实数据里会连同里程一起退出分子与分母，并在 `scope_note` 里点名长度。

### 用例 4 MQI 分级判定（四项分项齐全，落在优档下界）

权重 `mqi_weight.* = 55/15/20/10`（和 100，全部生效才有等级可判）：

- 路面 87.7、路基 95.0、桥隧 96.0、沿线 98.2 ⇒
  (55×87.7 + 15×95.0 + 20×96.0 + 10×98.2) / 100 = (4823.5 + 1425 + 1920 + 982) / 100 = 9150.5/100 = **91.505 → 91.5**
  ⇒ `status=ok mqi=91.5 grade=优`（`grade_threshold.mqi` 优档 `min=91.5`，`lower_inclusive` ⇒ 含界）
- 把沿线设施换成 97.2 ⇒ 91.405 → **91.4** ⇒ `grade=良`

边界探针（引擎实测）：`assign_grade(91.5)=优`、`91.4=良`、`91.6=优`、`79.25=良`、`79.2=中`。
含界与否由规则集登记，引擎不猜；而首期真实数据里 42 个对象的路段级 MQI 全是 partial ⇒
**等级字段一律为空**，不套用完整 MQI 的档位。

### 用例 5 年对比的变化贡献拆解（SYN-C1，2022 → 2023）

| 侧 | PCI | 扣分合计 | 分项得分 |
|---|---|---|---|
| 2022 | 87.7 | 12.3 | distress 99.4 / rq 85.0 / rutting 75.0 / skid 75.0 |
| 2023 | 82.3 | 17.7 | distress 99.0 / rq 80.0 / rutting 62.5 / skid 62.5 |

`compare` 输出：`status=ok delta=-5.4 劣化速率=5.4/年 length_overlap_m=1000.0`（正值 = 每年劣化多少分）。
`explain_change` 逐项（差值 = 后项扣分 − 前项扣分，舍入后为 0 的条目不列）：

- `pci_component.rutting`：车辙 6.0 → 8.0 mm ⇒ 扣分 3.8 → 5.6，差值 **1.8**（占比 0.333）
- `pci_component.skid_resistance`：抗滑 50.0 → 45.0 ⇒ 3.8 → 5.6，差值 **1.8**（0.333）
- `pci_component.ride_quality`：rqi 85.0 → 80.0 ⇒ 4.5 → 6.0，差值 **1.5**（0.278）
- `deduct_ratio.asphalt_distress`：坑槽/重 150 → 300 m²（回指台账行号 1）⇒ 0.2 → 0.3，差值 **0.1**（0.019）

Σ 列出差值 = 5.2，对 −delta = 5.4，残差 0.2 全部来自逐项显示值舍入——**不在项间摊分**
（口径同 `plan/05` §十）。`result_payload().top_contributors` 只带前 3 条（`TOP_CONTRIBUTOR_LIMIT`），
全量拆解走 `explain_change`（`rmqc compare` 的文本输出用它）。M6 的报告导出**没有**接 `explain_change`，
也没把 `top_contributors` 排进列：`PLAN_COLUMNS` / `PCI_COLUMNS` / `MQI_COLUMNS` 里没有贡献项列，
导出层只转述 `result_payload()` 已有的字段（口径见 `plan/02` §9 第 33 条）——
逐条变化贡献的拆解仍然只在 `rmqc compare` 面上，报告面不承担这件事、也不另算一份。

## 七、口径更正与已知不足

1. **误报分母 32 → 30（更正）**：M4 的写法按 distinct `segment_id` 从对象数里减，
   把"路段×年度"的年度维混掉了。现口径：42 个对象 − 12 个被**格级**注入标记的对象 = 30；
   划分变更标记对象留在分母里（它们本就不该有格级检出）。历史文档（`plan/03` §五、
   `plan/HANDOFF-M5.md` §〇）里的 0/32 按当时口径保留，不改写。
2. **划分变更的隐含结论按对象去重是 5**（按 finding 条数是 6）：M5 起统一按对象口径报，
   并在说明里写清算法（`detected_partition − partition_marks`）。
3. **等级判定准确率长期不可判**：除非拿到独立的规范等级真值（分级阈值原文），
   或引入第二套人工标注。把引擎自己算的等级当第二份真值是自证循环，本题明确不做。
4. **`coefficient_change` 这一档不可比因素仍判不了**：台账没有逐年登记规则集版本的表，
   系数变化只能靠换包版本表达并被 `rule_version_change` 捕获（`plan/05` §十）。
   要把它变成可测指标得先加台账版本表（schema 变更，需按 §9 登记并同步夹具）。
5. **内置包通路只证明"门在挡"**：它没有数值，因此复算误差/排序/汇总三项在这里只能是
   分母 0；真正的算术证据在夹具包通路，而夹具包不是规范口径（§一 已声明）。
6. **系数 14 格未解锁前，评测表不会变绿**：`jtst.mot.gov.cn` 在 M5 收尾时再次探测
   首页 / 检索页 / 详情页三种 URL 全部 503（`HANDOFF-M5` §二 第 10 条的可选重试无产出）。
